The 3 DIFFs are deliberate (docs/DIFFERENCES.md, "Google sign-in"):
- new user / replayed code (genuine half): same landing, users and session;
  Rails shows "Signed in with Google" on /accounts/new because its flash
  survives the /dashboard -> /accounts/new hop, Rust's does not (an existing
  self-hosted redirect chain; password sign-up loses its flash the same way).
- bad signature: Rails reads the identity from userinfo and never checks the
  ID token's signature on the code path, so a forged ID token signs in; Rust
  verifies it against the JWKS and refuses.

Note (2026-10-16, branch rails-bug-fixes, not re-run): reauthentication
is fixed in both servers. The button posts
/auth/google_oauth2?reauthenticate=<user|account> (no hidden field), and
any /auth/failure hit by a signed-in user is a failed reauthentication
(alert "Google could not confirm your identity. Please try again.",
/settings/members for "account", else /settings/profile). rails_reauth.rb
now runs the old form-field shape and the fixed query-string shape; the
latter is expected to confirm ("Identity confirmed. You can now
continue.", recently_authenticated: true). The 12 flows above don't touch
reauthentication, so 9/12 should be unchanged. "bad signature" remains a
deliberate difference, but not a Rails bug (DIFFERENCES Google item 1).
