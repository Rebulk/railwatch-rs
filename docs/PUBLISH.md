# Publish checklist: railwatch-rs v0.3.0

Status as of 2026-11-16. Everything here is prepared. **Nothing has been
published**: no new tag or GitHub release, no announcement. Cole approves
the publish.

## Ready

- [x] **Production runs the candidate.** railwatch.rebulk.com was swapped to
  `v0.3.0-rc.1` (main `bb56b05`) on 2026-11-16 04:29 UTC with
  `deploy/kamal-proxy/railwatch-swap`: requests were held 2.7 s and none was
  refused (an external `/up` probe got 54 of 54 `200`). After the swap:
  - `railwatch doctor` all ok, including a backup 38 s old
  - every production tenant's current-day file was written within seconds
  - THP is off in the process (`THP_enabled: 0`)
  - 479 MiB in the container right after start, against 1.7 GiB on v0.2.18
    after 37 h. Recheck this after a day of uptime.
- [x] Binary: built locally with `bin/release v0.3.0-rc.1` (the reproducible,
  digest-pinned builder the release workflow runs). x86_64 `SHA256SUMS`
  entry `53ca2cfa…`. The rollback binary is `bin/railwatch-green` /
  `railwatch.prev` (v0.2.18) on the box.
- [x] CI green on main (`ci`: fmt, clippy, tests, frontend, cargo audit,
  cargo deny).
- [x] README: install (one command), connecting a Rails app, running from
  source, release verification, and a benchmark summary with the test box
  stated. Full numbers in SCALE.md and RAILS-VS-RUST.md.
- [x] LICENSE: FSL-1.1-ALv2 (each release converts to Apache 2.0 after two
  years). THIRD-PARTY-LICENSES is generated by `bin/third-party-licenses`.
- [x] CHANGELOG.md with the v0.3.0 notes.
- [x] SECURITY.md and CONTRIBUTING.md are present.
- [x] Release pipeline: a `v*` tag builds both arches, signs SHA256SUMS
  keyless with cosign, and publishes. A `-rc.N` tag is marked pre-release,
  so `install.sh` and `railwatch upgrade` (which use `releases/latest`) do
  not pick it up. Tags are immutable (ruleset), so a tag cannot be re-cut.
- [x] Companion repos:
  - railwatch-cloud is marked a frozen reference (README banner, no
    features), and its bundler-audit advisories are fixed.
  - The `railwatch` gem is agent-only since 1.0.0. 0.x embedded-mode
    leftovers now fail with a migration message (unreleased, in its
    CHANGELOG).

## Needs Cole

1. **Go/no-go on the tag.** The repo is already public and v0.2.x releases
   exist, so tagging *is* publishing:
   ```sh
   git tag -s v0.3.0-rc.1 bb56b05 && git push origin v0.3.0-rc.1   # pre-release: not "latest"
   # after a soak on prod:
   git tag -s v0.3.0 <commit> && git push origin v0.3.0           # becomes latest; install.sh serves it
   ```
   The tag's CI build should give the same SHA256SUMS as the local build
   above (reproducible). Compare them before announcing.
